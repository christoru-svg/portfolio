Scaling the UX audit from a manual ritual to an AI skill

How I turned my heuristic evaluation process, done entirely by hand on Oodrive Sign, into a reusable AI skill for the whole product team.

Client
Oodrive (internal)
Role
Product designer
Duration
~1 week
Status
In use by the team
01 · Context

A solid heuristic evaluation that was impossible to reproduce consistently

At Oodrive, the UX audit (a heuristic evaluation based on Nielsen's method) is a go-to tool for challenging a product's experience before a major iteration. The first one I ran, on Oodrive Sign, was done entirely by hand: a Figma page with the 10-heuristic grid, screenshots pasted in one by one, a score calculated case by case, then a PowerPoint deck rebuilt from scratch for the readout.

Solid work, but slow and hard to reproduce consistently from one audit to the next. Every new evaluation started from zero.

Key takeaway: the first audit (Oodrive Sign) was 100% manual: a Figma grid, screenshots pasted one at a time, and a PowerPoint deck rebuilt from scratch for the readout.

02 · Problem

Redoing the same methodology work every time

A few months later, a new user need called for the same kind of audit on Oodrive Meet. It was a chance to avoid retracing the same path, but nothing in the existing process really made that possible.

  • No reusable framework: grid, severity scale and score calculation redefined for every audit
  • A readout deck (PowerPoint) rebuilt from scratch for every new evaluation
  • A method that lived in one person's head and couldn't be shared with the rest of the product team

“Stop redoing the methodology work every time, and turn the know-how gained on the Oodrive Sign audit into a process any designer on the team can reuse.”

Project goal
03 · Solution

A Claude skill that captures the entire method

Rather than keeping the method in my head, I turned it into a skill: a set of instructions and resources Claude follows for every new audit. It includes the definitions of the 10 heuristics and the severity scale, the formula for an overall score that's comparable across audits, the structure of the Word report, the Figma pitfalls I'd already run into, and a Figma Slides readout template in the Oodrive brand.

  • Figma grid filled in and annotated directly on the mockups, with a summary page and score
  • Structured Word report: summary up front, methodology and details at the end
  • Readout in Figma Slides using the Oodrive brand, or a PowerPoint deck depending on context
04 · Approach

How I ran the project

The skill didn't come from abstract thinking about the ideal audit: it came out of a second, real audit, run in parallel with building the skill itself.

Phase 1 · Baseline audit

Oodrive Sign, done by hand

Figma grid, screenshots pasted one by one, score calculated case by case, PowerPoint deck rebuilt from scratch. The method works, but it's entirely manual.

Phase 2 · Oodrive Meet audit

Reuse the template, delegate the evaluation

I reused the existing Figma template and handed screenshots to Claude to run the full heuristic evaluation: one finding per screen and per heuristic, a clear severity rating, and an actionable recommendation.

Phase 3 · Scaling up

Capture the method in a skill

I turned the process into a reusable skill (heuristics, severity scale, scoring formula, readout templates), then checked every deliverable against the same bar as manual work.

Leadership

From a personal tool to a team tool

Beyond a one-off audit, the goal was to save time for the whole product team, not just me. The method is now packaged in a file any designer can reuse, without rediscovering the same pitfalls (Figma mapping bugs, report structure, scoring formula).

The same method file can also be fed into Figma's native AI agents, to launch a heuristic evaluation without going through an external conversation.

What I'd do differently

The Figma readout file turned out to be a catalog of nearly 40 generic layouts rather than a pre-filled template: picking the right slides took longer than expected. The next version of the skill will document this catalog explicitly.
